# Resource Verification Methodology

## Core Principle
DealyVIP operates as a curated trust layer. We do not list broken links, fake APIs, or resources that cannot be independently validated.

## Validation Checklist
Before any resource is committed to the repository, it must pass the following checks:
1. **Existence:** The resource URL must resolve to a legitimate endpoint.
2. **Authority:** The operator must be clearly identifiable (e.g., "Turkish Patent and Trademark Office").
3. **Purpose:** It must be highly relevant to cross-border verification.
4. **Accuracy:** The description must reflect reality. If a registry requires a citizen login, it must be tagged as `LOGIN_REQUIRED`.
5. **Boundary Integrity:** No resource will be described as "guaranteeing" a safe transaction. 

## Terminology Enforcement
- **"Official government resource":** Domains ending in `.gov`, `.gov.tr`, `.gov.ua`.
- **"Institution / Chamber":** e.g., TOBB, ISO.
- **"Third-party platform":** e.g., YouControl, Opendatabot.

Under no circumstances should a third-party platform be labeled as an "official government registry".
